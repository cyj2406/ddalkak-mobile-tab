# 딸깍넷 — 반응형 UI 프로토타입

딸깍넷 AI 통합 서비스의 웹 UI 프로토타입입니다. 문서·PPT·이미지·영상·랜딩페이지·상세페이지를 대화형으로 생성하고, 만들어진 결과물을 뷰어와 미니 에디터에서 확인·편집하는 흐름을 담고 있습니다. 백엔드 없이 목업 데이터로 동작하는 화면 프로토타입이라, 생성·저장·다운로드는 실제 처리 없이 UI 상태만 바뀝니다. 모바일에서 시작해 태블릿·데스크톱까지 같은 코드로 대응하도록 확장했습니다.

주요 화면
- 홈 / 카테고리별 템플릿 갤러리 (이미지·랜딩·PPT·영상·문서·서식·오디오)
- 워크스페이스 (대화형 생성 → 상세 프롬프트 카드 → 결과물)
- 결과물 뷰어 (문서·PDF·엑셀·PPT·영상·이미지·웹) 및 미니 에디터
- 내 작업 / 즐겨찾기 / 크레딧 사용 내역 / 알림 / 설정

## 기술 스택

- **Vite 6** (빌드 · 개발 서버)
- **React 18** + TypeScript
- **Tailwind CSS v4** (`@tailwindcss/vite`)
- **shadcn/ui** (Radix UI 기반) · **lucide-react** 아이콘

## 로컬 실행

```bash
npm i          # 의존성 설치
npm run dev    # 개발 서버 (http://localhost:5173)
npm run build  # 프로덕션 빌드 → dist/
```

빌드 결과는 정적 파일이라 `dist/`를 아무 정적 호스팅에나 올리면 됩니다.

> 참고: 이 프로젝트에는 타입 체크 스크립트와 테스트가 없습니다. `npm run build`는
> Vite(esbuild)가 타입을 지우고 번들만 하므로 타입 오류를 잡아 주지 않습니다.
> 타입 검증이 필요하면 `typescript`를 devDependency로 추가하고 `tsc --noEmit`을 붙이세요.

│   │       ├── formfill/       # 서식 채우기 화면
│   │       ├── viewer/         # 결과물 뷰어 · 미니 에디터 (아래 설명)

`src/app/App.tsx`는 화면 대부분을 담은 큰 파일입니다. 화면을 찾을 때는 한글 섹션
주석(`// ─── 설정 모달 ───` 같은)으로 검색하는 편이 빠릅니다.

## 반응형 정책

### 폭 구간

| 구간 | 범위 | 성격 |
|---|---|---|
| 모바일 | ~600px | 한 손 조작. 바텀시트, 파일명 말줄임, 페이지 네비를 본문 위 플로팅 pill로 |
| 태블릿 | 600~1024px | 앵커된 팝오버, 상단바에 페이지 네비 |
| 데스크톱 | 1024px~ | 고정 사이드 컬럼, 라벨 노출 |

### 터치 분기

탭 영역은 **폭이 아니라 입력 방식**으로 가릅니다.

```css
@media (pointer: coarse) { /* 손가락 — 44px 이상 */ }
/* 그 외(마우스) — 32~36px */
```

폭으로 나누면 마우스를 쓰는 좁은 창에서 버튼이 불필요하게 커지고, 큰 태블릿에서는
반대로 작아집니다. 손가락으로 누르는지 여부가 실제 기준이라 `pointer: coarse`를 씁니다.

### 코드의 실제 경계값 (주의)

위 표는 **정책**이고, 코드에는 아직 이전 단계에서 굳어진 값이 남아 있습니다.
새로 만드는 화면은 위 정책을 따르되, 기존 코드를 읽을 때는 아래를 감안하세요.

| 값 | 쓰이는 곳 |
|---|---|
| `600px` | `max-width: 600px` — 모바일 전용 표현 (정렬 바텀시트, 파일명 말줄임, 페이지 네비 위치) |
| `768px` | Tailwind 기본 `md:` — 그리드 열 수, 모바일 안내 배너 노출 |
| `1024px` | Tailwind 기본 `lg:` |
| `1200px` | 커스텀 `wide:` (`--breakpoint-wide`) 와 `DESKTOP_MIN`. 데스크톱 판정의 실질 기준 |

즉 코드상 "데스크톱"은 **1024px가 아니라 1200px**입니다
(`viewerChrome.ts`의 `DESKTOP_MIN`, `theme.css`의 `--breakpoint-wide`).
정책과 코드를 맞추려면 이 두 값을 함께 옮겨야 합니다.

## UI 원칙

이번 반응형 작업에서 정한 규칙입니다. 새 화면을 추가할 때도 지켜 주세요.

**1. 정보 구조는 전 뷰포트 공통, 밀도와 컨테이너만 분기**

같은 기능이면 어느 폭에서든 항목 개수·문구·선택 표시가 같아야 합니다. 폭에 따라
달라지는 것은 밀도(간격·높이)와 담는 그릇(바텀시트 / 팝오버)뿐입니다. 모바일에만
다른 항목을 노출하거나, 선택 표시를 한쪽은 색으로 다른 쪽은 체크로 두지 마세요.

컴포넌트도 하나로 둡니다. 시트용·팝오버용을 따로 만들면 시간이 지나며 표현이 어긋납니다.
분기는 CSS 미디어쿼리 한 곳에서 처리합니다 (`theme.css`의 `.sort-menu`, `.filter-menu`).

**2. 메뉴 트리거는 아이콘 하나 = 메뉴 하나**

아이콘 전체가 단일 트리거이고, 누르면 메뉴가 열립니다. 본체와 화살표를 나눈
분할 버튼은 쓰지 않습니다.

셰브론(⌄)은 그것이 알려 줄 정보가 있을 때만 붙입니다. 아이콘을 누르면 무조건 메뉴가
열리는 경우 셰브론은 중복이며, 한 화면에 셰브론이 여럿이면 어느 쪽이 무슨 동작인지
구분되지 않습니다. 열림 상태는 `aria-expanded`와 트리거 배경 틴트가 전합니다.

선택지가 하나뿐이면 메뉴를 띄우지 말고 즉시 실행합니다
(예: 받을 파일이 하나면 다운로드 메뉴 없이 바로 내려받기).

**3. 터치 기기 최소 탭 영역 44px**

`@media (pointer: coarse)`에서 44×44px 이상을 확보합니다. 아이콘 글리프 크기는
그대로 두고 패딩으로 영역만 넓힙니다. 버튼 사이 간격도 함께 벌립니다(마우스 8px /
손가락 12px). 구분선 좌우는 버튼 간격보다 넓게 둬 그룹 분리가 읽히게 합니다.

**4. 그 밖에**

- 상단바 컨트롤에는 면(배경·테두리)을 두지 않습니다. 면을 가진 요소는 주요 동작
  하나(다운로드 파란 버튼)와 좌측 그룹 pill 하나로 제한합니다.
- 바텀시트에는 닫기(X)를 두지 않습니다. 그랩 핸들과 바깥 탭으로 닫히므로 중복이고,
  원형 면의 X가 제목과 시각적 무게를 나눠 갖습니다. 데스크톱 모달의 X는 유지합니다.
- 개수 배지는 0이면 렌더하지 않습니다. "0"을 보여 줄 이유가 없습니다.
- 메뉴는 `role="menu"` + `menuitem`/`menuitemradio`, 트리거는 `aria-haspopup`/
  `aria-expanded`. Esc·바깥 탭으로 닫히고 포커스는 트리거로 돌아갑니다.

## 배포

`main` 브랜치에 push하면 GitHub Actions가 빌드해 **GitHub Pages**에 올립니다
(`.github/workflows/deploy.yml`).

최초 1회만 저장소 설정이 필요합니다.

1. GitHub 저장소 → **Settings → Pages**
2. **Source**를 `GitHub Actions`로 변경

이후 배포 주소는 `https://<계정>.github.io/<저장소명>/` 입니다.
프로젝트 페이지는 하위 경로에서 서비스되므로 워크플로가 빌드할 때
`--base=/<저장소명>/`을 붙입니다. 저장소 이름이 바뀌어도 워크플로가
`github.event.repository.name`으로 자동으로 따라갑니다.

> 다른 호스팅을 쓴다면: 이 앱은 라우터가 없는 단일 페이지라 특별한 리라이트 설정이
> 필요 없습니다. Vercel·Netlify는 저장소를 연결하면 Vite를 자동 인식하므로
> 설정 파일 없이 `dist/`가 그대로 배포됩니다. 그 경우 `base`는 `/`이면 되므로
> 위 `--base` 옵션은 빼야 합니다.
